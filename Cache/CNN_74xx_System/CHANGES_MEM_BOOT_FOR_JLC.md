# 74 系列 CNN 系统工程 —— 存储器与扩展板接口改动报告（KiCad → 嘉立创 EDA 同步用）

日期：2026-11-10
基线：`CHANGES_V1_V11_FOR_EASYEDA.md` 完成后的嘉立创工程（12 板 Option A）
范围：S04 存储器阵列（B03）、S10 顶层 I/O（B12）、全工程常量 ROM 型号，
      以及第 4.4–4.6 节列出的引擎板必改项（V15/V17/V16）
不改：上述以外的板级结构、背板连接器、电源、时钟、复位

---

## 1. 结论速览

| 项目 | 改动 | 影响 |
|---|---|---|
| S04 权重存储器 | 4 片 `28C256` → `62256`（32K×8 SRAM） | **引脚完全兼容，封装不变，网络不变** |
| S04 偏置/qparam | 删除 8 片 `28C256`（U4012–U4019） | 这 8 片在当前 V2 requant 下没有任何读请求 |
| S04 去耦电容 | 56 只 → 48 只（删除 C4049–C4056） | 跟随删除的 8 片 |
| 全工程常量 ROM | 52 片 `27C512` → `W27C512` | **只改 Value，28 脚封装与网络不变** |
| S10 加载/状态接口 | `J10005`(2×16) + `J10006`(2×20) + `J10007`(2×10) → 新 `J10005`(2×32) | 三只合并成一只，新增 A15/START/RESET |
| S13/S15/S17 取位 | 固定右移 **8/9/8 → 9/10/9** | 每块 8 根取位线 + HIGH 或树，共三块 |
| S07/S08/S09 累加器 | **V15**：4 个 lane 计数器 /PE 补 `ACC_EN` | 每处只动 2 根线，不增删器件 |
| S07 卷积核计数 | **V17**：补零期间 KX/KY 清零（S08/S09 不需要） | 用板上空闲门，零新增器件 |
| 有符号乘法 | **V16**：LUT 有符号化 + ACC bit18..31 接 `BM17` | 重烧 32 片 LUT，每引擎 14 根线，零新增器件 |
| 新增网络 | `H_A15`、`START_RAW`、`RESET_RAW` 引到扩展板座 | 见第 7 节 |

改动后系统的上电流程变成：

```
扩展板上电 → 从 SD 读权重 → 通过 J10005 写入 4 片 62256
→ 回读校验 → 写 784 B 图像 → 置 IMAGE_DONE/MODEL_DONE
→ 释放 RESET、给 START → 状态机开始推理
```

因为 62256 是易失的，**每次断电后必须重新加载**。这是设计意图，不是缺陷。

---

## 2. 改动依据

1. **V2 requant 没有偏置**。`S13_Requant_C1` 图上写着 `C1 SIMPLE REQUANT - NO BIAS / NO ZERO POINT / FIXED >>8`，`docs/REQUANT_SIMPLE_V2.md` 也明确“没有 bias 加法器、没有零点、没有参数装载器”。因此 S04 的 4 片偏置存储器和 4 片 qparam 存储器**没有任何模块会去读**，属于上一版通用 requant 的遗留。
2. **AT28C256 写一个字节要 5 ms**，要把 14,472 B 权重从 SD 装进去需要 79 s（按 64 B 页写也要 1.3 s），不能作为“每次上电加载”的介质。62256 写一个字节约 0.5 µs，全部装完约 15 ms。
3. **AT27C512 已停产**，市面新片 `AT27C512R-70PU` 单价约 ¥15–21；`W27C512-45Z`（5 V、64K×8、DIP-28、电可擦写）约 ¥2.9–6.8，且读引脚与 27C512 完全一致。
4. 精度代价已实测：V2 契约（零 bias + 每层统一 2^S + 截断）在 10,000 张 MNIST 测试图上为 **97.83 %**，相对当前 int8 的 98.54 % 下降 **0.71 个百分点**；其中“去掉 bias”只占 0.07 pp。删除那 8 片本身不产生任何精度损失。

---

## 3. 编号约定（重要）

本次重生成后，S04 的位号发生了整体前移 8 号的变化（因为删掉了 8 个符号）。**嘉立创工程不要按位号硬对，按“器件值 + 功能描述 + 所在行”对齐**。

- 旧 `U4012–U4019`（28C256 bias/qparam）→ **已删除**，没有替代。
- 旧 `U4020–U4027`（27C512 LUT）→ 新 `U4012–U4019`，值改为 `W27C512`。
- 旧 `U4028–U4056`（S04 逻辑）→ 新 `U4020–U4048`，**统一减 8**。
  例：旧 `U4028`(74HC138) → 新 `U4020`；旧 `U4038`(74HC74) → 新 `U4030`；
  旧 `U4056`(74HC32, POOL1) → 新 `U4048`。
- FC2/POOL2 后加的 541 与 32：旧 `U4057–U4064` → 新 `U4049–U4056`。
- `U4001–U4011` 位号不变。
- S10：旧 `J10005/J10006/J10007` 删除，新 `J10005` 是**新加的 2×32 扩展座**，
  与旧的 `J10005`（IMAGE LOAD）不是同一个器件。`J10001–J10004` 不变。

## 4. 逐板操作

### 4.1 B03 S04_Memories（存储器阵列）

#### 4.1.1 删除 8 片 28C256

| 旧位号 | 值 | 功能（网络名） | 处理 |
|---|---|---|---|
| U4012 | 28C256 | 偏置 CONV1（`nCS_B_CONV1`） | 删除 |
| U4013 | 28C256 | 偏置 CONV2（`nCS_B_CONV2`） | 删除 |
| U4014 | 28C256 | 偏置 FC1（`nCS_B_FC1`） | 删除 |
| U4015 | 28C256 | 偏置 FC2（`nCS_B_FC2`） | 删除 |
| U4016 | 28C256 | qparam CONV1（`nCS_Q_CONV1`） | 删除 |
| U4017 | 28C256 | qparam CONV2（`nCS_Q_CONV2`） | 删除 |
| U4018 | 28C256 | qparam FC1（`nCS_Q_FC1`） | 删除 |
| U4019 | 28C256 | qparam FC2（`nCS_Q_FC2`） | 删除 |

删除后：

- 相应 8 个 `nCS_*` 网络不再存在；
- 4 个 74HC138 中，**旧 U4029（组 01，新 U4021）的 Y4–Y7** 与
  **旧 U4030（组 10，新 U4022）的 Y0–Y3** 变为空脚，
  在 KiCad 里标为 `NC`（No Connect）。嘉立创工程里请给这 8 个输出脚放“非连接”标记，
  不要悬空走线；
- `MEM_SEL = 12..15`（0x0C0000–0x0FFFFF）与 `16..19`（0x100000–0x13FFFF）
  变成未映射的保留窗口。译码逻辑本身不变，访问这些窗口时不会有任何片选。

#### 4.1.2 4 片权重 28C256 → 62256

| 位号 | 值（新） | 功能 | 窗口 |
|---|---|---|---|
| U4008 | 62256 | W_CONV1 | 0x080000 |
| U4009 | 62256 | W_CONV2 | 0x090000 |
| U4010 | 62256 | W_FC1 | 0x0A0000 |
| U4011 | 62256 | W_FC2 | 0x0B0000 |

**为什么可以直接换**：28C256 与 62256 都是 JEDEC 32K×8 / DIP-28，
关键脚位完全相同：

```
1=A14  2=A12  3..10=A7..A0  11..13=D0..D2  14=GND
15..19=D3..D7  20=/CE  21=A10  22=/OE  23=A11
24=A9  25=A8  26=A13  27=/WE  28=VCC
```

所以**封装、焊盘、走线、去耦、地址/数据/控制连接一律不动**，只改：
器件型号 → `62256`（推荐 `AS6C62256-55PCN` 或 `CY62256LL-70PC`）；
描述 → `32Kx8 SRAM ...`。

注意：KiCad 里符号已从 `Memory_EEPROM:28C256` 换成 `Memory_RAM:CY62256-70PC`，
但**电气连接一一对应**（数据脚在该符号里叫 `Q0..Q7`，/CE 叫 `~{CS}`）。
嘉立创工程如果只换型号，可以保留原来的 28C256 符号，不影响网表。

#### 4.1.3 去耦电容

每个 IC 一只 100 nF。删除 8 片后从 56 只降到 48 只，
删除的是**旧 C4049–C4056**（新图里不存在），其余 C4001–C4048 不变。

#### 4.1.4 不变的部分

- 7 片 6264（U4001–U4007）与全部地址/数据连接；
- 4 只 74HC138、74HC688、74HC04、74HC08、74HC157、2 只 74HC245、74HC74；
- `J4001`（2×12 本地加载/编程口）、10 只 10 k 上/下拉；
- `IMAGE_READY` / `MODEL_READY` 锁存（U4030，原 U4038）。

> 说明：`J4001` 原描述是“Image load and EEPROM programming header”。
> 现在没有 EEPROM 了，它只剩“本地加载权重/图像”的用途，描述已改为
> `Image / weight load header (companion to J8)`。位置和引脚不变。

### 4.2 B12 S10_Top_IO（扩展板接口）

> 本节 U91–U98 是嘉立创工程当前的 S10 位号；参考 KiCad 重建后为
> U10001–U10009，按“器件值 + 连接”对齐。

#### 4.2.1 删除三只连接器

| 旧位号 | 规格 | 值 | 处理 |
|---|---|---|---|
| J10005 | 2×16 | IMAGE LOAD | 删除 |
| J10006 | 2×20 | PARAM PROG | 删除 |
| J10007 | 2×10 | STATUS | 删除 |

#### 4.2.2 新增 J10005（2×32，64 脚）

- 器件：`Connector_Generic:Conn_02x32_Odd_Even`
- 封装：`Connector_PinHeader_2.54mm:PinHeader_2x32_P2.54mm_Vertical`
  （想用 IDC 排线座就换 `Connector_IDC:IDC-Header_2x32_P2.54mm_Vertical`，焊盘需相应调整）
- 值：`EXPANSION`，描述：`Expansion-board port: load, start, reset, status`
- 位置：原三只旧座（J10005/J10006/J10007）的区域，或 S10 左下，
  不与电源座 J10001 重叠

**为什么是 64 脚而不是 60**：三只旧座合计 32+40+20=92 个物理脚，
其中 `D[7:0]`、`LOAD_EN`、`LOAD_nWE`、`LOAD_nOE` 和电源各重复了三份，
合并后只保留一份；地址取并集并从 15 位扩到 16 位；再补上原来在
`J10002`(START) / `J10003`(RESET) 上的两根。**功能一根没少。**

#### 4.2.3 新增的三根连接

| 信号 | 来源/去向 | 说明 |
|---|---|---|
| `H_A15` | J10005.26 → U94.7 → ADDR15 | 原来 U94 已经缓冲了 H_A15，只是旧 J6 没引出 |
| `START_RAW` | J10005.37 → U91 同步器 → `START` | 与 J10002 同节点；J10002 保留作调试用 |
| `RESET_RAW` | J10005.38 → U70A/B 整形 → `RESET_N` | 与 SW1/J10003 同节点；**外部必须开漏驱动** |

> `RESET_RAW` 上有 R1 100 k 上拉、C90 1 µF，SW1 按下时直接对地。
> 扩展板如果用推挽输出高电平，会和 SW1 形成短路。**要求开漏（或串 1 k）**。

#### 4.2.4 不变的部分

- `U92`(74HCT245) 数据收发、`U93/U94`(地址)、`U95`(地址标签)、`U96`(MEM_SEL+WE/OE)；
- `U97/U98`(74HCT541) 状态缓冲，`ST_*` 仍驱动 D1–D7 LED；
- `J10001` 电源座、`J10002` START、`J10003` RESET、`J10004` 外部时钟、SW1、R1/C90、X1/JP1；
- 原来的 16 只 `H_A` 下拉（RN1/RN2）、5 只 `H_MEM_SEL` 下拉、控制上拉。

### 4.3 S13 / S15 / S17：取位移位 8/9/8 → 9/10/9

#### 4.3.1 为什么必须改

这三块的右移量是**硬接线**的（没有跳线、没有寄存器）。原来接的是
Conv1=8、Conv2=9、FC1=8。用最终权重实测：

| 移位 | 准确率（10,000 张 MNIST） |
|---|---:|
| 8 / 9 / 8 | **25.64 %** |
| 9 / 10 / 9 | **97.83 %** |

`S` 小一位，右移结果整体翻倍，绝大多数激活值撞到 255 饱和，
信息全丢。**这不是掉几个点，是直接失效。**

> 新工程（按模块面积拆分的那版）网络连接与主工程完全一致，
> 所以这条改动在新工程里同样适用，改法完全相同。

#### 4.3.2 逐块改法

每块 8 根取位线 `QRAW0..QRAW7 = ACC[S+0 .. S+7]`，整体上移一位；
同时 `HIGH = OR(ACC[S+8..31])` 的低端也上移一位（少一个输入）。
`NEG = ACC[31]` 和 `SAT_POS = HIGH & ~ACC[31]` 不变。

S13_Requant_C1（P = `C1`，8 → 9）：

| 网络 | 旧 | 新 |
|---|---|---|
| `C1_RQ_QRAW0` | C1_ACC8 | **C1_ACC9** |
| `C1_RQ_QRAW1` | C1_ACC9 | **C1_ACC10** |
| `C1_RQ_QRAW2` | C1_ACC10 | **C1_ACC11** |
| `C1_RQ_QRAW3` | C1_ACC11 | **C1_ACC12** |
| `C1_RQ_QRAW4` | C1_ACC12 | **C1_ACC13** |
| `C1_RQ_QRAW5` | C1_ACC13 | **C1_ACC14** |
| `C1_RQ_QRAW6` | C1_ACC14 | **C1_ACC15** |
| `C1_RQ_QRAW7` | C1_ACC15 | **C1_ACC16** |
| `C1_RQ_HIGH` | OR(C1_ACC16..31) | **OR(C1_ACC17..31)** |

S15_Requant_C2（P = `C2`，9 → 10）：同上，所有位号 +1。

| 网络 | 旧 | 新 |
|---|---|---|
| `C2_RQ_QRAW0..7` | C2_ACC9..16 | **C2_ACC10..17** |
| `C2_RQ_HIGH` | OR(C2_ACC17..31) | **OR(C2_ACC18..31)** |

S17_FC1（P = `FC1`，8 → 9）：同上，所有位号 +1。

| 网络 | 旧 | 新 |
|---|---|---|
| `FC1_RQ_QRAW0..7` | FC1_ACC8..15 | **FC1_ACC9..16** |
| `FC1_RQ_HIGH` | OR(FC1_ACC16..31) | **OR(FC1_ACC17..31)** |

S17_FC2 的路径**不变**：FC2 不做 requant，直接 32 位原始 ACC 按小端
四字节输出，四根字节选择线 `BC[1:0]` 不动。

#### 4.3.3 操作要点

- 网络名 `*_RQ_QRAW0..7` 不变，只改它们接到哪一根 ACC 上；
- `HIGH` 是一棵或树，输入从 `ACC[S+8]` 开始。改完后最低那一根不再参与，
  或树少一个输入；按新图重连，不要只把标签改名；
- 原理图上的标题文字也要改：`FIXED >>8` → `FIXED >>9`、`FIXED >>9` → `>>10`、
  `FC1 >>8` → `FC1 >>9`（新图已经改好，照抄即可）；
- 三块都是同一套电路，只有前缀不同，可以逐块对照改；
- 改完用网表核对：S13 应只用到 `C1_ACC9..31`，S15 只用到 `C2_ACC10..31`，
  S17 的 FC1 路径从 `FC1_ACC9` 开始（FC2 路径仍用 0..31）。

#### 4.3.4 打板前必须再做一次

`S` 由最终权重标定出来的累加器满量程决定。**投板前用最终权重重新标定**：

1. 跑校准集，记录每层 `|ACC|max`；
2. `S = floor(log2(|ACC|max / 255))`；
3. 如果结果还是 9/10/9，直接投板；
4. 如果变了，改 `tools/build_requant_simple.py` 的 `SHIFT` 重新生成这三块，
   再同步到嘉立创工程——要改的就是上面三张表里的位号。

原理图没有跳线可选，所以这一步必须在投板前定死。

### 4.4 S07 / S08 / S09：V15——四块引擎的累加器永远不装载（必改）

#### 4.4.1 现象

四块引擎都能发写周期，但写进 SRAM 的数据恒为 0；仿真里 `ACC_LD` 一次都不出现。

#### 4.4.2 根因（已用波形证实）

每个引擎是 4 lane 并行 MAC。lane 计数器（74HC161）在 E_ACC 状态计数 0→1→2→3，
`LANE_LAST = LANE0 & LANE1`，`ACC_LD = ACC_EN & LANE_LAST`。
但现在的 /PE 是：

```
LANE_PE_N = ~(LANE0 & LANE1)          ← 少了 ACC_EN
```

74HC161 的 /PE 是**同步**装载，且不受 CEP/CET 门控：Q=3 的下一个时钟就装 0。
于是：

```
第 3 次 E_ACC 后 Q 变成 3，但此时已经离开 E_ACC；
下一拍 Q 立刻被 /PE 清 0；
第 4 次 E_ACC 看到的是 Q=0 —— Q=3 永远不与 ACC_EN 重叠 → ACC_LD 恒 0。
```

波形（状态 7 = E_ACC）：

```
ST=00111 q=0010 PE_N=1 ACC_EN=1
ST=00010 q=0011 PE_N=0        ← 离开 E_ACC 后才到 3
ST=00011 q=0000               ← 立刻被清 0
```

#### 4.4.3 四处改法（每处只动 2 根线，不增删器件）

| 板 | lane 计数器 | /PE 门 | 现在 | 改为 |
|---|---|---|---|---|
| S07 / B04 | U7140 | U7022 第 4 门（p11 输出） | p12=LANE0，p13=LANE1 | p12=**LANE_LAST**，p13=**ACC_EN** |
| S08 / B06 | U8141 | U8142 第 1 门（p3 输出） | p1=LANE0，p2=LANE1 | p1=**LANE_LAST**，p2=**ACC_EN** |
| S09_FC1 / B08 | U9127 | U9015 第 4 门（p11 输出） | p12=LANE0，p13=LANE1 | p12=**LANE_LAST**，p13=**ACC_EN** |
| S09_FC2 / B09 | U9327 | U9215 第 4 门（p11 输出） | p12=LANE0，p13=LANE1 | p12=**LANE_LAST**，p13=**ACC_EN** |

> 旧分析文档把 FC2 的计数器写成 U9209。U9209 是 74HC688（INDEX 比较器），
> FC2 的 lane 计数器是 **U9327**；上表已按当前网表逐脚核对。

改后：

```
LANE_PE_N = ~(LANE_LAST & ACC_EN)
```

正好是“第 4 个 MAC 的 E_ACC 周期同步清 0”，同时 `ACC_LD = ACC_EN & LANE_LAST = 1`。

#### 4.4.4 验收

- 改前（仿真日志）：`ACC_LD pulses = 0`，C1OUT 恒 0。
- 改后：E_ACC 且 LANE=3 时 `ACC_LD=1`；每个输出点的 MAC/装载次数：
  Conv1 **28/7**、Conv2 **72/18**、FC1 **400/100**、FC2 **32/8**。
- `Simulation/rtl/cnn74_top.v` 里已有的 V15 修改只是**仿真 ECO**，不在原理图里；
  打板必须按上表改，否则四块引擎全部输出 0。

### 4.5 S07：V17——补零期间 KX/KY 被推进（必改；S08/S09 不需要）

#### 4.5.1 根因

Conv1 每个输出点 25 个真实抽头，4 lane 分组固定要 28 步，末尾 3 步是补零
（`PAD_ACTIVE=1` 把 B 强制为 0）。现在：

```
KX_PE_N = ~(KX_LAST & MAC_EN)
KY_PE_N = ~(KXKY & MAC_EN)
```

第 25 个 MAC 时 KX=4、KY=4，两个 /PE 同时为 0，KX/KY 被同步清 0；
接下来 3 个补零 MAC 里 KX_LAST=0，于是 KX 又数 0→1→2。
下一个输出点的第一个 MAC 从 KX=3 开始，只走 22 个真实抽头，权重整体错位。

仿真（修复前）：`p0: MAC=28, LD=7`，`p1: MAC=25, LD=6`，之后继续错。

#### 4.5.2 S08 / S09 为什么不用改

- Conv2：8×3×3 = **72** MAC/点，72 ÷ 4 = 18 整组，没有补零周期；
  当前网表里也没有 `C2_PAD_ACTIVE` 这类信号。
- FC1：400 MAC/点，400 ÷ 4 = 100；FC2：32 MAC/点，32 ÷ 4 = 8。
- 只有 Conv1 的 25 ÷ 4 余 1，才有 3 个补零步。

所以旧分析里“S08 U8019 第 1/2 门也要改”**不成立**；S08 照改反而会在正常
MAC 期间错误清 KX/KY。`cnn74_top.v` 的 V17 ECO 也只加在 C1 上，与这里一致。

#### 4.5.3 S07 改法（用板上空闲门，零新增器件）

现有：

- U7021 第 1 门：p1=KX_LAST，p2=MAC_EN → p3=KX_PE_N
- U7021 第 2 门：p4=KXKY，p5=MAC_EN → p6=KY_PE_N

板上空闲门（当前网表确认未用）：

- U7143（74HC32）第 3 门：p9、p10 → p8；第 4 门：p12、p13 → p11
- U7155（74HC04）第 5 门：p11 → p10；第 6 门：p13 → p12

可用的中间信号：

- U7019 p6 = `KY_EN` = `KX_LAST & MAC_EN`
- U7019 p11 = `OX_EN` = `KXKY & MAC_EN`
- U7143 p3 = `PAD_ACTIVE`

步骤：

1. 断开 U7021 p3 与 KX_PE_N、p6 与 KY_PE_N（p3/p6 悬空；p1/p2/p4/p5 保留）。
2. U7143 p9←`KY_EN`，p10←`PAD_ACTIVE`；p8 得到 `KY_EN | PAD_ACTIVE`。
3. U7155 p11←U7143 p8；p10 输出 = **KX_PE_N**。
4. U7143 p12←`OX_EN`，p13←`PAD_ACTIVE`；p11 得到 `OX_EN | PAD_ACTIVE`。
5. U7155 p13←U7143 p11；p12 输出 = **KY_PE_N**。

逻辑：

```
KX_PE_N = ~(KY_EN | PAD_ACTIVE) = ~(KX_LAST & MAC_EN) & ~PAD_ACTIVE
KY_PE_N = ~(OX_EN | PAD_ACTIVE) = ~(KXKY & MAC_EN) & ~PAD_ACTIVE
```

补零期间 /PE 恒为 0，74HC161 每个时钟都同步装入 0（不是“保持”），
所以 KX/KY 在 3 个补零步里保持 0；第 25 个 MAC 时它们已经清 0，
下一个输出点从 (0,0) 开始。

> 注意：**不能**把 /PE 直接和 PAD_ACTIVE 相或——那样补零时 /PE=1，计数器会继续数。
> 必须是“与 ~PAD_ACTIVE”，或先或再取反（上面用的就是后者）。

如果转换后的嘉立创工程把 U7143/U7155 的空闲单元丢了：新增 1 片 74HC08
（两个与门）+ 1 片 74HC04（两个反相器），按 `/PE = 原NAND输出 & ~PAD_ACTIVE`
接，不要动计数器本身。

#### 4.5.4 验收

- 修复后每个点都是 28 MAC / 7 次装载；C1 的 `ACC_LD` 总数 = 点数 × 7。
- 仿真里加 RTL ECO 后为 `ACC_LD=4032=576×7`（只跑了 576 个点）。

### 4.6 V16：有符号权重乘法（投板前必须定方案，不属于“小修”）

#### 4.6.1 事实（逐项核对过）

- LUT 地址 = `{A[7:0], B[7:0]}`，A 是激活、B 是权重（网表 A15..A8=A，A7..A0=B）。
- 当前 `tools/gen_lut.py` 生成的是**无符号** `A*B`（0..255 × 0..255）。
- V2 权重是**有符号 int8**（−127..127，二进制补码；见 `FPGA_CNN/eval_v2_quant.py`）。
- 4 个乘积用 18 位无符号加法树相加，ACC 的 bit18..31 加 0，没有符号扩展；
  requant 却把 ACC 当 signed 32 位（ACC31=1 → Q=0，SAT_POS 饱和）。
- 结果：负积在 16 位补码里是 0x8000..0xFFFF 的大正数，被当成正数累加；
  C1OUT 大量 0xFF、FC1OUT 全 0xFF、8 组测试向量 0/8。

#### 4.6.2 三个方案

| 方案 | 内容 | 改板量 | 精度 |
|---|---|---|---|
| A. 非负权重 | 权重限制 0..255，重新训练/导出；LUT 仍无符号 | 不改板，但要重训 + 重标定移位 | 97.11 %（10 k） |
| B. 常数偏置 | LUT 存 `a*w + 32768`，每层减去 `32768*N`（N=25/72/400/32） | 每引擎 8×74HC157 + 常数，或 32 位减法器 | 与 V2 同级 |
| C. 有符号加法树 | LUT 存有符号积；ACC 高位补符号 | 见 4.6.3，**零新增器件** | 97.83 %（10 k）/ 97.5 %（2 k） |

> 任务书禁止“擅自重新训练、修改权重”，所以方案 A 只有在用户明确授权新模型时才能用。
> 推荐 C：不碰权重、不改精度、几乎不改板。

#### 4.6.3 C 的最小实现（比旧分析少很多）

旧分析写“每级 2 个 XOR、每引擎 3–4 片”，其实**不需要**：
当前 74HC283 树已经把 4 个乘积加成 `PSUM[17:0]`，而且 bit16-19 那一级已经有一个
`BM17 = ACC_LD ? PSUM17 : 0` 的 74HC157 输出（S07 U7102 p7）。它就是现成的、
带 ACC_LD 门控的符号位。只要把它接到 ACC 的 bit18..31 即可。

**步骤 1：重烧 32 片 LUT ROM（每引擎 8 片）**

```
p = a * (b if b < 128 else b - 256)   # 16 位二进制补码
LO = p & 0xFF,  HI = (p >> 8) & 0xFF
```

位号（偶数=低字节，奇数=高字节，按 lane 成对）：

- S07：U7077–U7084
- S08：U8078–U8085
- S09_FC1：U9063–U9070
- S09_FC2：U9263–U9270

> 当前 `model/lut/lut_lo.bin` / `lut_hi.bin` 是无符号的，必须重新生成；
> 这只影响烧录文件，不改板。
>
> 权重字节必须是 **int8 二进制补码**（−127..127 直接存 0x81..0x7F），
> 不能是旧 V1 的偏移二进制（`w+128`）。如果扩展板装载的是 `w+128` 的旧映像，
> 方案 C 不成立，必须先换成 V2 导出的补码权重。

**步骤 2：每引擎把 14 个高位加法器的 B 输入从 GND 改接到本引擎的 `BM17`**

| 板 | 16-19 位那片的 p15、p11 | 20-23 / 24-27 / 28-31 三片，每片 p6、p2、p15、p11 | BM17 来源 |
|---|---|---|---|
| S07 | U7107 | U7108 / U7109 / U7110 | U7102 p7 |
| S08 | U8108 | U8109 / U8110 / U8111 | U8103 p7 |
| S09_FC1 | U9093 | U9094 / U9095 / U9096 | U9088 p7 |
| S09_FC2 | U9293 | U9294 / U9295 / U9296 | U9288 p7 |

注意：16-19 位那片的 p6、p2 已经分别接 `BM16`、`BM17`，不要动；只改 p15、p11。

为什么正确：

- 每个乘积是 16 位补码；4 个乘积之和 ∈ [−129540, +129540]，正好落在 18 位补码范围；
- 现有树输出的 `PSUM[17:0]` 就是这 4 个有符号积的精确 18 位补码和；
- `BM17 = ACC_LD ? PSUM17 : 0` 是门控后的符号位；把它接到 bit18..31，
  等效于 `ACC += sign_extend_18(PSUM)`；
- ACC 是 32 位补码，总量不超过 ±2^31，不会溢出；
- requant 保持 9/10/9（4.3 节）不变。

电气：BM17 从 1 个负载变成 15 个 HC 输入（约 50 pF），74HC157 在 8 MHz 下带得动。

如果不想动 14 根线，方案 B 也行，但要多 8 片/引擎的 74HC157 和常数网络，
不推荐。

**W27C512 的关键事实**：

- 5 V、64K×8、DIP-28、45 ns、电可擦写，可反复烧；

> 并改封装 + 增加地址线；本次不做。

```
11. 等 ST_DONE = 1，读 ST_RESULT[3:0]
```

## 8. 权重与量化（给权重生成脚本的约束）

当前 74 系列硬件实现的是 V2 requant：

```
Conv1 / Conv2 / FC1 :  Q = clamp(ACC >> S, 0, 255)
FC2                 :  原始 signed 32 位 ACC，小端 4 字节
```

- `ZP_X = ZP_W = ZP_OUT = 0`，**bias 必须为 0**；
- 每层一个统一的 2 的幂，不允许 per-channel M/S；
- 没有四舍五入，直接算术右移。

**实测移位（用当前训练权重在 10,000 张测试图上标定）**：

| 层 | 最佳 S |
|---|---:|
| Conv1 | **9** |
| Conv2 | **10** |
| FC1 | **9** |

> `tools/build_requant_simple.py` 的 `SHIFT` 已经改成 `{"C1": 9, "C2": 10, "FC1": 9}`，
> S13/S15/S17 的取位线也按这个值重新生成。
> 同一份权重用旧的 8/9/8 只有 **25.64 %**，不是掉几个点，而是直接失效。
> 详细对照见 4.3 节。

精度：V2 契约下 97.83 %（当前 int8 98.54 %），差 0.71 pp；只去 bias 差 0.07 pp。
